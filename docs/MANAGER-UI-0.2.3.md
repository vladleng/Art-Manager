# Arranger Manager 0.2.3 — графитовый UI (Issue #61 / PR #62)

## Контекст

Пользователь показал два дефекта UI 0.2.2 на Windows: синеватые оттенки нейтральных поверхностей/подписей и белую системную строку заголовка «Arranger Manager 0.2.2» над графитовым приложением. Этот уточнённый срез реализован в ветке `feature/61-task-create-routing-0.2.3` и пока **не слит** в main.

## Изменено

- В `MRManagerStyle.h` сделан отдельный **runtime-only графитовый слой нейтральных токенов**: canvas, panel, channel, item, selected, section, outline, bright, meta, muted, focus. Синие оттенки в контуре, тексте, фокусе и выделении заменены на нейтральные серые.
- `MRManagerAssets.h` — **генерируемый файл**, исходные MR UDS SVG/manifest, инструмент `embed_mr_manager_assets.py` и MR Studio/Live **не изменялись**. Отдельный Manager-профиль отрисовки намеренно не заменяет закреплённую upstream-библиотеку. Нейтральные SVG-иконки действий, которые хранят старый синий `#91BBEE`, перекрашиваются **только в памяти** через `Drawable::replaceColour` при создании кэша. Цветные status glyphs не трогаются.
- `HubWindow` вместо `setUsingNativeTitleBar(true)` использует `setUsingNativeTitleBar(false)` и graphite background `mr::colour(mr::tokens::panel)`. JUCE рисует тёмную шапку и оконные кнопки без зависимости от светлой темы Windows.
- Значения `wip`/`wait`/`done`/`blocked`/priority P1–P4/`progressFill` сохранены как **смысловые индикаторы**; прогресс и данные задач не меняются.
- Новый набор assertions в `TaskTreeUiTests`: нейтральные цвета без голубого подтона, нейтральная SVG-иконка действительно отрисовывается серой; семантические цвета неизменны.
- Дополнительно #61: при создании обычной задачи теперь остаёмся в списке, не открываем полноэкранный TaskDetails.

## Windows-приёмка (только после успешного CI)

1. Открыть Desktop 0.2.3. Проверить, что **верхняя строка «Arranger Manager 0.2.3» тёмная**, меню Workspace и оболочка без синеватой окраски, контраст текста и фокуса достаточен.
2. Проверить двойной клик заголовка, перенос окна, минимизацию/максимизацию/закрытие, изменение размеров окна, поведение при пользовательском масштабе Windows (DPI).
3. Проверить статусы WIP/WAIT/DONE, приоритет P1–P4 и зелёный progress: их цвета **не должны исчезнуть**.
4. Создать задачу в «Все задачи», в разделе страницы и из другого раздела — после сохранения должна показываться строка задачи без автоматического полного окна свойств.

## Не входит в данный PR

Переработка **типов страниц «Заметки на полях»** и удаление чекбоксов подзадач остаются несделанными пунктами Issue #61; будущий контекстный редактор свойств тоже отдельно. Merge в main **только с явного согласия пользователя**.

## Статус

Код, проверка графитовой палитры и тест SVG-иконок опубликованы. Windows CI после полной серии UI-изменений (включая кэш иконок и цвет заголовка) инициирован этим коммитом; результат **ещё не установлен**. Физическая Windows-проверка оконных контролов/DPI — **NOT TESTED**, до прохождения CI никаких заявлений о приёмке.
