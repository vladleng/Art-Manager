# #54-A / 0.2.1 — первое развитие TaskDomain (исходный код, ещё без сборки)

**Status:** source-only / NOT TESTED / NOT ACCEPTED. Ветка `feature/54-task-domain-0.2.1` от принятого `main` (Manager 0.2.0). Родитель #54, подэтап #57. Данный срез не завершает все UI-требования #54.

## Решение по данным

- Для **обычных** `WorkspaceTask` добавлено необязательное поле `parentTaskId`. У прежних schema2 записей оно отсутствует и трактуется как пустое (задача верхнего уровня). Формат workspace остаётся schema2: это совместимое добавление, не переписывание каталога и не автоматическая миграция чек-поинтов.
- Новая подзадача — полноценная задача со своими ID, Notes, статусом, приоритетом и блоками. Старые `TaskCheckpoint` и `catalog.songs[].tasks/checkpoints/localNotes` хранятся по-прежнему и остаются доступны. В одном дереве могут быть и новые дочерние задачи, и прежние checkpoint-leaves.
- `WorkspaceModel::validate()` проверяет цепочки parent, owner, циклы и глубину до 8 уровней. `WorkspaceQueries` скрывает задачи с архивным предком и возвращает только корневые записи в `allTasks`; `TaskTreeRows` строит вложенные обычные задачи из этих ссылок.
- Новая guarded команда `createSubtask(parentId, name, outId)` добавляет дочернюю задачу только под доступным обычным владельцем. `moveTask(taskId, expectedOwner, expectedParent, destinationOwner, destinationParent, beforeSibling)` атомарно меняет owner/parent у root и всего поддерева; переставляет root по исходным ID, проверяет конфликт исходных полей, недопустимый drop, archived/missing/цикл/глубину. Не копирует задачи; запись идёт через общий `WorkspaceController` + `WorkspaceStore`.
- `reorderCheckpoint(taskId, checkpointId, beforeId)` меняет порядок старых checkpoints одной обычной задачи с сохранением ID/Notes; для старых song/catalog checkpoints отдельного переноса между владельцами нет.
