## Исправление прогресса вложенных задач — 0.3.0-Upd1-fix2

Контракт локальной шкалы: для задачи с дочерними задачами в `total` входят **все активные задачи-потомки** (каждая по одному элементу) и **все активные checkpoint-листья** самой задачи и потомков. В `done` входят только элементы со статусом `DONE`. Статус родительской задачи **не равен** рассчитанному progress и не меняется автоматически. Архивированные потомки, их вложенные элементы и архивированные checkpoints исключаются; восстановление возвращает их в расчёт. Для задач без вложенности старая формула checkpoint `DONE/count` сохраняется. Старые DAW-каталоги и их семантика не затрагиваются.

Регрессия: доменный тест проверяет два уровня вложенности, переход DONE, общий расчёт со старыми checkpoints, независимость родительского статуса, Undo, архив/восстановление. UI тест измеряет изменение фактически нарисованного progress-bar после DONE у вложенной задачи. Нет изменений JSON/schema.

# #38 / 0.3.0 — «Сегодня»: контракт первого технического среза

База: принятая 0.2.7, merge `fd8f58cb72b2932e278558f07c3a9c3c2317fcb2`. Это первый кандидат этапа #38, **не** полное закрытие планирования дня.

## Реализовано в первом срезе

- Локальный `WorkspaceTask.plan`: `start`, `end`, `deadline`, `completedAt`. Поля необязательные, прежний `schemaVersion: 2` и старые JSON без поля `plan` открываются без миграции/перезаписи; старые ID и Notes не меняются.
- Дата без времени в виде `YYYY-MM-DD` и локальная дата-время `YYYY-MM-DDTHH:mm`; это **локальные гражданские** даты рабочего пространства, не UTC и не время музыкального проекта. Валидатор отказывает в неправильных датах и в конце интервала раньше начала. Если конец не задан, интервал длится один календарный день. Отдельный дедлайн допустим без плана.
- `WorkspaceCommands.updateTaskPlan` с CAS-проверкой ожидаемого значения, сохранение через существующий Controller/Store, Undo, backup; не создаёт копий задач.
- `TodayPlanning.tasksForDay(model, day)` возвращает существующие TaskReference.ID, разделяет незавершённые запланированные, просроченные дедлайны и выполненные. Учитывает многодневные интервалы, исключает архив и offline legacy. Это **проекция**, не отдельное хранилище.
- Раздел `Сегодня` в боковой панели; поле выбора даты (в формате `YYYY-MM-DD`, Enter) и информация о количестве запланированных, просроченных и завершённых. В таблице показываются незавершённые запланированные и просроченные задачи; контекстное меню обычной задачи → `Запланировать / изменить сроки…` открывает компактный редактор Start/End/Deadline и очистку интервала. Ошибка оставляет черновик.
- Сохранён действующий Notion-like графитовый вид, общий TaskTree и контекстное редактирование; чек-поинты не дублируются как отдельные дневные задачи.
- Автоматические `TodayPlanningTests`: даты/високосный год/interval/overdue, CAS, Undo, roundtrip, schema2 без новых полей, invalid data и неизменность ID/owner.

## Ограничения текущего среза (ещё в #38)

- **Часовой пояс:** действующий `WorkspaceModel.timezone` по умолчанию `Asia/Krasnoyarsk`. Начальная выбранная дата вычисляется для UTC+7; переключение IANA timezone и DST-aware расчёт текущего дня пока **не реализованы**. Выбранную дату можно ввести вручную; не трактовать предварительный UI как полную реализацию timezone requirement.
- Отсутствуют: быстрые действия «на завтра», дневной ручной порядок и фильтр по проекту; история `completedAt` ещё не записывается автоматически при смене статуса; отдельное представление завершённых задач и визуальное разделение просроченных в таблице. Завершённые пока отображаются в счётчике, но не отдельным списком.
- Перенос с удалением и восстановлением сохраняет существующие ID; подробные регрессии UI/DPI, полночь, timezone, multi-day проходят позже в #38.
- Ни MR Live, ни MR Studio адаптеры не добавляются.
